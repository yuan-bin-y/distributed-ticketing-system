## 已完成能力

- 用户注册、登录、刷新凭证与退出；BCrypt 密码摘要、RSA JWT、Redis 会话。
- Gateway 路由、响应式身份检查；业务服务独立校验用户身份及订单归属；内部协作使用分方向服务凭证。
- 管理员创建完整活动草稿、查看准备进度、按原参数重新准备、全部库存准备完成后发布。
- 已发布活动分页、详情、场次与票档查询。
- 订单价格快照、购买幂等、同用户同场次跨票档累计限购。
- 库存初始化、预留、确认售出、释放及查询；数据库条件更新控制不超卖。
- 创建支付单、模拟付款、可靠 HTTP 通知、回查付款事实、无法履约时全额模拟冲正。
- 未支付到期关闭、异常重试、进度持久化、宕机恢复和竞争处理。
- 成交后生成唯一电子票，查询本人订单与电子票。

一次订单购买一个票档，可购买多张；同场次重复购买受累计限购约束，并非一律禁止第二次购买。

## 交付数量

共有六个独立启动的服务，公共模块 `ticket-common` 和 `ticket-security` 通过 Maven 依赖使用，不独立启动。

| 服务 | 默认端口 | 业务库 | 业务表 |
| --- | --- | --- | --- |
| Gateway | 8060 | 无 | 无 |
| Event | 8061 | ticket_event | t_event、t_event_session、t_ticket_tier |
| Order | 8062 | ticket_order | t_order、t_order_item、t_ticket、t_user_session_quota |
| Inventory | 8063 | ticket_inventory | t_ticket_stock、t_stock_reservation |
| Payment | 8064 | ticket_payment | t_payment、t_payment_reversal |
| Auth | 8065 | ticket_auth | t_user |

五个业务库共 12 张业务表，另各有一张 `flyway_schema_history`，合计 17 张表。该数量来自当前迁移文件；既有本地库是否已迁移至最新版取决于服务启动情况，不包含 Nacos 自身数据。

## 验收与性能结论

功能验收的 80 项真实 Nacos/Gateway 检查、95 项累计限购回归、137 项支付履约回归全部通过。测试使用隔离数据，包含服务停机恢复、重复请求、响应丢失、到期关闭和迟到付款补偿。

单机有限请求测试中，单热点票档下单吞吐约 60～65 请求/秒。256 个工作线程、每组 1,000 次下单的对照中，Inventory 连接数从 10 增至 30 收益有限；同场次十个票档分散请求达到约 152 请求/秒。两轮对照共 8,000 次下单最终预留成功，订单与库存核对通过。测试环境、HTTP 延迟及最终业务结果的区别见原始报告。

性能结果用于说明本机测试现象，不代表生产容量或完整支付出票吞吐。第一版保留现有应用参数，速度优化安排到第二版。

## 第一版范围边界

当前通过 API 演示后端，没有配套业务前端。支付、冲正均为模拟，没有真实资金操作。电子票提供票号及查询，没有二维码入场核验。

管理员支持完整草稿创建与发布，暂不支持编辑初始化参数、下架、取消场次或修改已准备库存。还未接入 MQ、Outbox、Nacos 配置中心、网关限流、熔断、完整分布式追踪、多机部署与持续容量验证。

## 第二版候选工作
